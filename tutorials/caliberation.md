# Eye-to-Hand Camera Calibration Guide

## Overview

This project uses an **Eye-to-Hand calibration**.

The camera is fixed above the workspace while the robot moves underneath it.

The objective of calibration is to compute the rigid transformation

T_base_camera

which converts any 3D point measured by the camera into the robot base coordinate system.

After calibration, every trajectory generated from the camera can be executed by the robot.

---

# Coordinate Systems

There are two coordinate systems.

Camera Frame

```
           Z
           ^
           |
           |
           O ------> X
          /
         /
        Y
```

Robot Base Frame

```
          Z
          ^
          |
          |
          O ------> X
         /
        /
       Y
```

Calibration computes

Robot Point = T_base_camera × Camera Point

# Step 1 – Load RGB Image

```python
img = cv2.imread(FRAME_PATH)
```

This loads the RGB frame used to select calibration points.

---

# Step 2 – Load Depth

```python
depth = np.load(DEPTH_PATH)
```

The depth image contains one depth value for every pixel.

Depth is stored in meters.

---

# Step 3 – Load Camera Intrinsics

```python
K = np.load(INTRINSICS_PATH)
```

Example

```
fx = 1046.81
fy = 1046.81

cx = 1120.22
cy = 627.01
```

These are the intrinsic parameters of the ZED camera.

# Step 5 – Compute Stable Depth

Instead of using a single pixel,

the notebook computes the median depth inside a small window.

```python
patch = depth[v-2:v+3, u-2:u+3]
```

This removes noisy measurements.

---

# Step 6 – Convert Pixel to Camera Coordinates

Each pixel

(u,v)

is converted into

(X,Y,Z)

using

```
X = (u-cx)*Z/fx

Y = (v-cy)*Z/fy

Z = depth
```

The output is

```
Camera Points

[
[X1 Y1 Z1]
[X2 Y2 Z2]
...
]
```

These points are expressed in the camera coordinate system.

---

# Step 7 – Validate the Plane

All calibration points lie on the same wooden board.

Therefore their depth values should be similar.

The notebook checks

```python
z_range = max(Z)-min(Z)
```

If

```
z_range < 0.20 m
```

the calibration continues.

Otherwise

the selected pixels are incorrect.

---

# Step 8 – Plane Normalization

The notebook optionally replaces every Z value by the average depth.

```python
camera_points[:,2] = np.mean(camera_points[:,2])
```

This reduces sensor noise.

---

# Step 9 – Record Robot Coordinates

Jog the robot TCP to exactly the same six physical points.

Example

```python
robot_points = np.array([

[1070.165,237.981,383.461],

[1070.163,-236.051,383.461],

...

])/1000
```

Important

Convert mm to meters before computing the transform.

---

# Step 10 – Compute Rigid Transformation

The notebook uses SVD (Kabsch Algorithm).

```
Camera Points

↓

Rotation

↓

Translation

↓

Robot Points
```

Result

```
T_base_camera

4×4 matrix
```

```
[R t]

[0 1]
```

This matrix is saved as

```
T_base_camera.npy
```

---

# Step 11 – Verify Calibration

Each camera point is transformed

```
Robot Prediction

=

T

×

Camera Point
```

The predicted robot point is compared with the measured robot point.

The notebook prints

```
Errors (m)

Mean Error
```

Good calibration

```
< 10 mm
```

Acceptable

```
10–20 mm
```

Poor

```
>20 mm
```

Your current notebook reports approximately

```
Mean Error ≈ 0.116 m
```

which is approximately

```
116 mm
```

This indicates that calibration should be repeated with better point selection or more calibration points.

---

# Step 12 – Transform Trajectories

Once calibration succeeds,

every trajectory point

```
[x,y,z]
```

generated by the vision pipeline is transformed by

```python
robot_point = T @ camera_point
```

The transformed trajectory is then executed by the robot.

---

# Saving the Matrix

```python
np.save("T_base_camera.npy",T)
```

This file should be reused for all future trajectories as long as neither the camera nor the robot base moves.

---

# When Must Calibration Be Repeated?

Calibration must be repeated if

- camera position changes
- camera angle changes
- robot base moves
- table moves
- camera is replaced
- lens is changed

Otherwise,

the same matrix can be reused indefinitely.

---

# Common Errors

## FileNotFoundError

```
reach_traj.npy not found
```

The trajectory file is missing or the path is incorrect.

Verify

```
/content/drive/MyDrive/
```

contains the file.

---

## Large Calibration Error

Possible causes

- inaccurate robot TCP positions
- wrong pixel selection
- noisy depth
- points too close together
- camera moved during calibration

---

## Bad Plane Detection

If

```
Z range > 0.20 m
```

then the selected points are not on the same flat surface.

Choose new points.
